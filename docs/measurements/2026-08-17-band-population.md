# Relevance band 由「命中通道數」決定時的帶內分佈（2026-08-17）

Refs #24、change `fix-band-semantics-and-turn-identity` task 1.1。

這份量測是一道**否決閘**，不是事後說明。change 的 `retrieval` spec 寫著：channel-count
分層在被採用之前，其帶內分佈必須先被量測；**若分佈退化就作廢規則、停下重新裁決**。
兩種退化各自的理由：

- 幾乎每個候選都只命中一條通道 → 幾乎全部同一帶，band 不再提供相關度邊界
- 幾乎每個候選都命中三條 → 每帶只剩少數候選，接近「每筆自成一帶」的原缺陷

**結論：不退化，規則可採用。** 依據在下方。

## 方法

- **索引**：206 chunks，取自 97 個 project 各一個 session 檔（每檔 60–200 KB），
  以 `ltm build` 建立。機器：MacBook Pro M5 Max，macOS 27.0，SQLite 3.54.0，
  embedding revision `12784592-5D67-4F4C-83D6-A346519146AE#1`。
- **查詢**：30 個人工挑選的詞（中英混合、長度 2–10 字），`--k 20`、`--all-projects`。
- **測得值**：每個候選的 `channels` 欄位（由 `ltm query --json` 輸出），據以算命中通道數
  與每個帶的候選數。
- **候選總數**：600（30 查詢 × 20）。

## 結果

### 命中通道數

| 命中通道數 | 候選數 | 佔比 |
|---|---:|---:|
| 3 條 | 51 | 8.5% |
| 2 條 | 137 | 22.8% |
| 1 條 | 412 | 68.7% |

### 通道組合

| 組合 | 候選數 | 佔比 |
|---|---:|---:|
| `vector` | 379 | 63.2% |
| `segment` + `vector` | 77 | 12.8% |
| `segment` + `trigram` | 53 | 8.8% |
| `segment` + `trigram` + `vector` | 51 | 8.5% |
| `segment` | 33 | 5.5% |
| `trigram` + `vector` | 7 | 1.2% |

### 帶內候選數

| 指標 | 值 |
|---|---:|
| 帶總數 | 54 |
| 帶內候選數 min / median / max | 1 / 12 / 20 |
| 單一候選（該帶無法重排） | 4（7%） |
| 可重排的帶 | 50（93%） |

每個查詢的帶結構多為兩帶（例：`測試` → `{2 條: 6, 1 條: 14}`），少數為單帶
（例：`錯誤處理` → 全部命中 1 條）。

## 判讀

**不退化。** 68.7% 命中單一通道**不構成** spec 寫的「nearly every candidate matching
exactly one channel」——31.3% 的候選落在更高的帶，而且 93% 的帶內有多於一個候選，
策略在帶內有實際的移動空間。分層與可重排性同時成立，這正是規則要達成的效果。

**一個結構性事實值得記下來**：`vector` 單獨命中佔 63.2%，因為 cosine 對任何查詢都會
回傳最近的 k 個（always-on），而 FTS5 需要實際的字面匹配（conditional）。所以「只命中
一條通道」在實務上幾乎等同於「只被向量找到」。這反而支持分層——同時被 lexical 通道
找到的候選，其相關度證據確實比只有向量鄰近性的候選強。

## 這份量測涵蓋什麼、不涵蓋什麼

**涵蓋**：在 206-chunk 索引上，人工挑選的 30 個查詢所產生的帶結構。

**不涵蓋**：

- **真實規模**。本專案的完整語料約為此索引的三個數量級以上。索引變大時 lexical 通道的
  命中數會增加，分佈可能偏移。本量測**不能**用來宣稱大索引上的分佈。
- **真實查詢**。30 個查詢是人工挑的，不是使用日誌。查詢分佈一變，帶結構就會變。
  真實查詢集要等 #16 的評估集建立。
- **排序品質**。本量測完全不涉及「這個分層讓結果變好或變壞」——那需要 ground truth，
  而本專案還沒有。**任何引用本檔來支持排序品質的說法都是誤用。**
- **`--k` 的影響**。`--k 20` 對 206-chunk 索引約為 10%。更大或更小的 k 會改變帶結構
  （k 越大，越後段的弱候選越多，單一通道的比例越高）。

## 重測觸發

以下任一發生時本檔的數字作廢，需重測：

- tokenizer 配置變更（會改變 lexical 通道的命中集合）
- embedding revision 變更（會改變 vector 通道的排序）
- RRF 的 k 常數變更
- 語料規模成長超過一個數量級
- #16 的評估集就緒後（屆時應以真實查詢重測，本檔的人工查詢只作結構性參考）
