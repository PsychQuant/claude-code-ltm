# docs/measurements/ — 量測紀錄的使用規則

每一份紀錄自己寫明它涵蓋什麼、不涵蓋什麼；引用時**指名出處**（CLAUDE.md 誠實邊界）。
本檔只放跨紀錄共用的規則。

## 基準查詢使用規則（#63）

### 為什麼需要規則

任何在 Claude Code session 裡輸入或印出的字串，都會進 `~/.claude/projects/**/*.jsonl`，然後進索引。
所以**在 session 裡跑量測，查詢字串就會污染下一次量測**：#56 量測時的一行 Bash 命令
（含三個基準查詢的逐字）被索引後，v0.4.0 實測三個查詢的第一名全部是那一則命令
（#62 的重現：工具 metadata chunk 三通道全中、band 0；真正談那件事的 turn 只中向量、band 2）。
從那一刻起，這三個查詢量到的是「自己的量測命令有多好找」。

### 查詢集在哪、怎麼用

- 查詢集：`scripts/baseline-queries.txt`（一行一條、`#` 註解）。它的檔頭寫著同樣的規則——兩處要一起改。
- 量測：`scripts/measure-baseline.sh [k]`——讀檔、逐條 `ltm query --k <k> --json`，**stdout 只印
  `#N <ms> clean|dirty|error(rc)`**。`#N` 是檔內第 N 條非註解行。密鑰用命令替換餵進環境
  （`LTM_ANCHOR_KEY="$(~/bin/ltm memory --export-key)" scripts/measure-baseline.sh`），不落地。
- `dirty` 的判準（封閉列舉，會漏）：前 k 名任一 chunk 的 snippet 以 `⟨tool ` 開頭，或含 `ltm query`。
  dirty 不是錯，是「這條查詢的命中品質這一輪不可比」；耗時仍可比。

### 三條規則

1. **查詢字串不得以明文出現在會進語料的地方。** 具體：不在 session 裡 `cat`／`echo`／`Read` 查詢檔、
   不把查詢原文貼進對話、不在 Bash 命令列上帶查詢（`⟨tool Bash command=…⟩` 的 `command=` 前 200 字元
   會被索引）。編輯查詢檔用 Write／Edit 工具（其 `content` 欄位不在索引欄位清單裡）或在 Claude Code
   之外的編輯器。
2. **量測輸出只印編號。** 命中內容、snippet、查詢文字一律不印；要看命中內容，在 Claude Code
   **之外**的 shell 跑（那個 shell 的逐字稿不在語料裡）。
3. **每次量測前重驗。** 選定當下乾淨不代表永遠乾淨——跑一次 `measure-baseline.sh`，dirty 的條目
   在那一輪的命中品質欄標記為不可比。

### 它擋不住什麼（誠實寫下）

- 人手在 session 裡貼了查詢原文，或 Claude 自己 Read 了查詢檔——規則靠人守，沒有機制擋。
- 語料裡本來就有恰好含該字串的**實質** turn（例如退役查詢裡的「資格考」有一則真的使用者 turn）——
  那不是污染，是正常召回；`dirty` 判準不會標它，讀結果時要分辨。
- 未來新的工具殘影形狀（判準是封閉列舉）。

### 退役清單（已污染，不得再用）

「tokenizer 討論」「flock inode 鎖」「資格考」——2026-08-08 至 2026-09-01 的紀錄用它們量**耗時**的部分仍可讀；
命中品質從 2026-09-01T04:32Z（污染 turn 的時間）起不可比。相關紀錄的可比性註記見各檔。

### 與其他 issue 的關係

- #62（self-hit 的檢索層排除）：會讓工具殘影的第一名掉下去，但不會讓已污染的查詢恢復成乾淨基準——
  它的前後量測是本查詢集的第一個消費者。
- #33（評估集）：真正的解是 `(查詢, 應命中的 turn)`；本查詢集只是把儀器擦乾淨，說不出代表性。
