# 首次全量 build 的中斷觀察（#44 / #45）

**日期**：2026-08-26
**binary**：`.build/release/ltm`，commit `2d2a6cb`（**分批提交之前**）
**語料**：9,851 個 `.jsonl`／5.6 GB（本機 `~/.claude/projects/`）
**性質**：**一次未受控的臨場觀察，不是對照實驗。** 見最後一節的證據等級。

> 這份紀錄是補寫的。`1 小時 20 分`、`WAL 751 MB` 這兩個數字先前被寫進
> `IndexBuilder.swift` 的註解、CHANGELOG 與 v0.3.0 的 release notes，而
> `docs/measurements/` 裡沒有任何東西可以指。本 repo 的誠實邊界寫著「沒有量測
> 支撐的宣稱不得出現」，所以要嘛補紀錄、要嘛刪宣稱。這裡選補——因為觀察確實
>發生過——但**同時標明每個數字的來源與可信度**，不讓補紀錄變成事後追認。

## 觀察到的時間序列

以下有時間戳、且**在 issue body 裡留有紀錄**（`#44` / `#45` 開票時逐字寫下）：

| 時刻 | 已跑 | `index.sqlite3` | `index.sqlite3-wal` | RSS | 外部看到的 `chunks` |
|---|---|---|---|---|---|
| 15:35 | 0 | 4 KB | 4 KB | — | 0 |
| 15:51 | 16 分 | 4 KB | 21 MB | 2.1 GB | 0 |
| 16:00 | 25 分 | 4 KB | 128 MB | 0.7 GB | 0 |
| ~16:08 | 33 分 | 4.0 KB | 240 MB | 2.1 GB（峰值）| 0 |
| 16:15 | 40 分 | 4 KB | 289 MB | 2.2 GB | 0 |
| 16:16 | 41 分 | 4 KB | 358 MB | 2.2 GB | 0 |

三件事可以從這張表直接讀出來，不需要外推：

1. **`index.sqlite3` 全程停在 4 KB**，WAL 單調成長。整份工作在單一交易內，
   一個 byte 都沒有 checkpoint 進主檔。
2. **外部讀取者看到的 `chunks` 全程是 0。** 這是「中斷 = 全丟」的直接證據——
   40 分鐘的工作對任何其他行程都還不存在。
3. **RSS 不單調**（2.1 → 0.7 → 2.2 GB）。所以「峰值 RSS」這個量在這一輪裡本身
   就有大幅擺盪，單點取值不可靠。這一條後來在
   [`2026-08-26-build-peak-memory.md`](2026-08-26-build-peak-memory.md) 被合成語料
   的對照證實：RSS 的成長來源尚未被隔離量測定位。

## 最終狀態：證據等級較低

**`1 小時 20 分`、`WAL 751 MB`、中斷後 `chunks` 為 0** —— 這組數字**只出現在
commit `414fc73` 的訊息裡**，沒有對應的原始輸出、沒有 issue body 紀錄、沒有截圖。

它與上表的趨勢一致（WAL 從 358 MB 繼續長、build 從 41 分鐘繼續跑），所以不是憑空
編的；但它**沒有被獨立記下來過**，所以不能與上表同等看待。引用時請引用上表，
或明說引用的是這一段。

## 查法（任何人可重跑）

```bash
# 另開一個終端機，build 跑的期間：
ls -l  ~/.claude-ltm/index.sqlite3 ~/.claude-ltm/index.sqlite3-wal
ps -o rss= -p "$(pgrep -x ltm)"          # KB
sqlite3 ~/.claude-ltm/index.sqlite3 'select count(*) from chunks'   # 外部讀取者
```

第三行是關鍵：交易未提交時它回 0，而 `ltm` 自己的行程看得到未提交的資料。
**兩邊不一致就是「這份工作還不存在」的證據。**

## 這份紀錄支持與不支持的結論

**支持**：

- 分批提交之前，全量 build 的中間結果對外部讀取者完全不可見。
- WAL 在單一交易下單調成長到數百 MB 量級。
- 全量 build 的耗時是**小時**量級（至少 41 分鐘仍在跑，有時間戳）。

**不支持**：

- 任何「全量 build 要跑 T 分鐘」的預測。這是**一台機器、一份語料、一次**的觀察，
  沒有重複、沒有對照，而且中途被中斷所以連完整耗時都沒有量到。
- 任何「峰值 RSS 是 X」的陳述——同一輪內 RSS 在 0.7–2.2 GB 之間擺盪。
