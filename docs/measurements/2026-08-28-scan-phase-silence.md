# 掃描階段的沉默有多久（#48）

**日期**：2026-08-27（全量 build 當次的觀察，紀錄補寫於 2026-08-28）
**機器**：MacBook Pro M5 Max（18 核、128 GB）
**binary**：`.build/release/ltm`
**語料**：9,935 檔／5.7 GB → 658,450 個新 chunk

## 觀察到的時間軸

```
0 – 310 秒    掃描                                    ← **零輸出**

> **時代註記（#47）**：這個 310 秒量在「前綴重讀＋重算」還存在的 scanner 上
> （#49 已刪一次、#47 的增量雜湊再刪一次讀取）；未 pin commit。現行 scanner 的
> 掃描時間未重量——引用這個數字時要說它是**舊讀取模式**下的觀察。
310 秒        掃描完成：9935 個來源檔，658450 個新 chunk
310 秒起      … 嵌入 200/658450 chunk（已用 2 秒）      ← 每 200 chunk 或每 5 秒
```

`ltm build` 的第一行進度是掃描**結束**時印的，所以在它之前有一段約五分鐘、
stderr 完全沒有輸出的區間。使用者在那段時間看到的與「卡死」一模一樣。

## 這份紀錄的等級

**這是一次觀察，不是受控量測。** 一台機器、一次、沒有重複、沒有點內變異，
也沒有與別的規模對照。

它足以支撐的：**「掃描階段確實有一段以分鐘計的沉默」**——那是 #48 的前提，
而它為真。

它**不足以**支撐：任何「每 GB 幾秒」的外推、任何跨機器的預測、任何「310 秒是
典型值」的說法。要那些東西需要重複與多規模點，本紀錄沒有。
