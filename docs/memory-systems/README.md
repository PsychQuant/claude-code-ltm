# 記憶系統：可比較的策略空間

本專案刻意**不選定**單一記憶模型。不同策略在同一份語料、同一組查詢上跑，可以比較——
這一頁定義比較的框架，各策略的細節另立檔案。

## 為什麼保留這個軸

設計過程中出現過一次關鍵反轉，值得記錄，因為它會一再出現：

初版設計把「提取次數影響排序」列為三大風險（富者愈富、popularity bias、可重現性斷裂），
主張用 ±5% 封頂把它壓到幾乎無效。反駁是一句話：

> 你的批評其實剛好是人類記憶系統的缺點吧

這是對的。提取練習效應（retrieval practice）、可得性捷思（availability heuristic）、
重建式記憶（Bartlett）——**被列為缺陷的三件事，正是人類記憶的真實特徵**。把它們消掉
不是「修正錯誤」，是**選擇了另一種記憶模型**（檔案櫃），而那個選擇被偷渡成了預設值。

所以策略不該寫死在架構裡。**它是參數，不是前提。**

## 比較的三個軸

| 軸 | 問題 | 極端 A | 極端 B |
|---|---|---|---|
| **保真** | 回傳的是原文還是改寫？ | 逐字原文 | LLM 摘要 |
| **可重現** | 同一 query 兩週後結果一樣嗎？ | 完全確定 | 受使用歷史調變 |
| **關聯** | 命中會不會擴散到相鄰記憶？ | 只回命中 | 擴散激發 |

三軸互相牽制：關聯擴散提高召回但傷可重現；LLM 摘要提高可讀性但傷保真。
**沒有全贏的點**，所以要能量測、能切換。

## 候選策略

各策略共用同一個檢索底座（BM25 + 向量 RRF），差別在記憶層怎麼介入。

| 策略 | 記憶層行為 | 像什麼 | 狀態 |
|---|---|---|---|
| `archival` | 無。純內容相關性排序 | 檔案櫃／grep | 已實作（`LTMQuery`）|
| `human-like` | power-law decay + 提取增強，帶內重排、位移有上限 | 人腦 | **部分實作**（`LTMQuery`）|

> **`human-like` 缺一個機制，這裡明說。** issue 要的第三個機制是 **spreading
> activation**（Collins & Loftus, 1975；issue 裡叫「共現擴散激發」，Clarity Surface
> 已裁決共現實作只是它的一個變體）——**目前沒有實作**。它需要一個共現邊結構，
> 而事件 schema 還沒帶那個東西；補上去會讓這次改動超出「定義 seam」的範圍。
> 列為 follow-up。
>
> 這條記在這裡，是因為先前的 `proposal.md` 把 "co-retrieval association" 列進
> 已 ship 的機制、本表也標成「已實作」——那是過度宣稱，由 #1 的 verify
> （2026-08-11）抓出並更正。**部分實作就寫部分實作。**

### 移除的第三檔：`conservative`

原本還有一檔 `conservative`（「strength 只當 tie-breaker，影響封頂 ±5%」）。它被**移除**，
理由不是取捨而是**那條規則無法表達**：

RRF 分數是 rank 導出的、且與查詢相對——同一個數值差在不同查詢裡意義不同，而且輸入清單
深度一變，分數分佈就跟著移動。所以「±5%」沒有穩定的指涉對象，實作出來的東西不會是規格
說的那件事。它倖存下來的那部分約束（只在同一相關性帶內重排、位移有上限）不是一個獨立
的檔次，而是 `human-like` 本身就該遵守的性質，已經內建。

**如果日後要第三檔，必須用「消費哪些訊號」定義**（例如 `explicit-only`：只吃 cited 與
pinned），**不得用調整幅度定義**。這條在 code 裡也是硬的：`MemoryStrategy` 有一個
`consumedSignals` 成員，而同一個策略配不同位移上限回報同一個 id。策略軸的語意是
「有沒有記憶」，不是「記憶多強」。

### 位移上限預設 1 —— 這個數字是暫定的

`human-like` 的位移上限是建構期參數，預設 1，**在文件與 doc comment 兩處都標記為
provisional**。帶內有 20 個候選時，被引用十次的 anchor 也只能上移一名，這很可能過度
保守；但反方向同樣沒有證據支持任何特定數字。在評估集就緒之前它定不出正確值，所以留成
參數並記錄未定，而不是挑一個看起來合理的數字假裝它有依據。

`human-like` 的公式直接沿用 `PsychQuant/ai4o` 的 `docs/memory/implementation/`
（`memory-strength.md` / `consolidation.md`），那套已按 Wixted & Ebbesen (1991) 的
power-law 調過，不重推。

**一處刻意的偏離**：AI4o 會把低 strength 記憶 `archived = true` 排除於候選之外，
理由是省 recall window 的 token。claude-LTM 是全庫檢索、沒有 window 壓力，照抄
archive 會讓正回饋**把記憶永久埋掉**。因此 `human-like` 的低 strength 只回到中性
（boost = 1.0），永遠留在候選集。

## 評估：沒有 ground truth 就沒有比較

策略可切換只解決一半；另一半是**怎麼知道哪個比較好**。

評估需要一組 `(查詢, 應該命中的 turn 指標)`。這組資料只能從真實回溯情境累積——
每次實際用 claude-LTM 找東西並找到了，就記一筆。**冷啟動時它是空的，這是誠實的
限制，不是可以繞過的細節。**

在有評估集之前，任何「策略 X 比較好」的說法都沒有根據，包括本文件的推薦。

### 比較方式是 interleaving，不是重放歷史查詢

重放歷史查詢是標準做法，也方便得多——但它需要留著 query 原文，而 query 經常含第三方
姓名與未發表內容，記憶層的硬約束把它擋在外面。**不留 query 是隱私決定，比較方式改用
interleaving 是這個決定的直接後果，不是疏忽。**

做法：同一次查詢由兩個策略各出排序，交錯成一份清單呈現，看使用者點開哪一邊
（team-draft）。只需要已經同意記錄的事件（`shown` / `opened` / `cited`）。代價是**回溯式
比較不可能**——只能比較「現在這兩個策略」，不能拿舊資料重跑一個新策略。

兩個伴隨的紀律：

- **報告一律分桶，不得只給整體數字。** #2 的實測顯示向量融合的整體 +1pp 增益 100% 集中
  在中文雙字桶；只看整體會判成「沒有差異」。分桶用的是一個封閉五值的 query class label
  （`cjk-2char` / `cjk-3char` / `cjk-4plus` / `latin-alnum` / `mixed`），它從 query 算出後
  query 即丟棄——label 是統計不是內容，所以它可以留，原文不行。
- **兩邊排序相同時不記給任何一方**（null comparison）。硬記會憑空製造偏好。

預期結果值得先講明：`archival` 與 `human-like` 在**整體**上很可能統計不可分辨。這不是
實作失敗，是效果量本來就可能小於雜訊——所以逐桶那幾列才是要看的東西。
