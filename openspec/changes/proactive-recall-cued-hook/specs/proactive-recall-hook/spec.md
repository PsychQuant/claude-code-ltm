## ADDED Requirements

### Requirement: A cue-gated prompt hook injects pointered recall within the hook budget

The plugin SHALL register a `UserPromptSubmit` hook. When `LTM_RECALL_MODE` is unset or `cued`, the hook SHALL gate in two stages: a cheap raw match of the cue file against the whole hook input (before any parsing), and — only when that matches — a confirming match against the prompt text after removing any `<system-reminder>…</system-reminder>` spans. It SHALL run `ltm query` only when both match. The raw stage is an over-approximation (it may match a cue in a non-prompt field or inside a system-reminder); the confirming stage removes those. A prompt that fails the raw stage costs only bash and grep and SHALL NOT start the extraction subprocess. When the mode is `always` the hook SHALL run `ltm query` for every admitted prompt. When the mode is `off` the hook SHALL exit 0 with empty stdout without reading the cue file. An unrecognised mode value SHALL behave as `cued` and SHALL say so on stderr once per session.

When the hook runs `ltm query` it SHALL pass `--format recall`, `--k 3`, `--max-refresh-seconds <guard − 5, at least 1>`, `--exclude-session <session_id>` when the hook input carries a `session_id` matching `[A-Za-z0-9._-]{1,128}` (an id that does not match SHALL be treated as absent, not passed), then `--`, then the prompt text (at most 4,000 characters, cut at a character boundary) as the last argument, so a prompt beginning with `-` is never parsed as an option. It SHALL run the query from the hook's `cwd` so the query scope is that directory's project. The `ltm` binary SHALL be `LTM_BIN` when set, else `$HOME/bin/ltm`, and SHALL be an absolute path — a relative `LTM_BIN` is a degradation, because the executable check and the execution happen on different sides of the `cd`. The hook SHALL never exit with status 2 and SHALL never emit a `decision` of `block`.

#### Scenario: Cue match injects a recall block

- **WHEN** the mode is `cued` and the prompt is `上次那個 flock 的決定是什麼`
- **THEN** the hook's stdout is a block that begins with `<!-- ltm:recall v1 -->`, ends with `<!-- /ltm:recall -->`, contains at most three hits each carrying a project, a timestamp, a snippet, and a `turn <uuid>` pointer, and contains no hit whose sessions set is exactly the hook's `session_id`

#### Scenario: No cue match costs nothing

- **WHEN** the mode is `cued` and the prompt is `幫我改這個函式`
- **THEN** the hook exits 0 with empty stdout, runs no `ltm` process and no extraction subprocess, and finishes in under 100 ms (the raw stage is grep-only; measured p50 ≈ 21 ms)

#### Scenario: Prompts generated by Claude Code itself are never admitted

- **WHEN** the prompt text (after system-reminder removal and leading whitespace) begins with `<`, `Base directory for this skill`, `This session is being continued`, `(Re-invocation of`, or `Stop hook feedback:` — the five shapes Claude Code produces for slash-command expansion, skill bodies, compaction continuation, skill re-invocation, and Stop-hook feedback — and the mode is `cued` or `always`
- **THEN** the hook treats it as a gate miss and injects nothing, regardless of cue matches inside the text. This is a closed list and will miss new shapes; the cost of a miss is one unwanted recall.

#### Scenario: The prompt is passed after a terminator

- **WHEN** the admitted prompt is `--k 99 上次 flock`
- **THEN** `ltm query` receives it as the single positional argument after `--`, and the query still runs with `--k 3`

#### Scenario: Injections from other hooks cannot trigger recall

- **WHEN** the prompt text itself contains no cue but a `<system-reminder>` span inside the prompt contains the word `earlier`
- **THEN** the hook treats the prompt as a gate miss and injects nothing

#### Scenario: Mode off is silent

- **WHEN** `LTM_RECALL_MODE=off` and the prompt matches a cue
- **THEN** the hook exits 0 with empty stdout

##### Example: Gate outcomes

| `LTM_RECALL_MODE` | Prompt | Runs `ltm query` | stdout |
| ----------------- | ------ | ---------------- | ------ |
| unset | `上次那個 flock 的決定是什麼` | yes | recall block |
| unset | `幫我改這個函式` | no | empty |
| `always` | `幫我改這個函式` | yes | recall block |
| `always` | `Stop hook feedback:\n上次 flock` | no | empty |
| `off` | `上次那個 flock 的決定是什麼` | no | empty |
| `bogus` | `上次那個 flock 的決定是什麼` | yes | recall block |

### Requirement: The hook's subprocesses run under one deadline, and degradation is visible and never blocks the prompt

The hook SHALL compute one absolute deadline at start — `LTM_RECALL_GUARD_SECONDS` seconds after launch, default 20, non-numeric values treated as 20, and clamped below the manifest timeout so the script always speaks before Claude Code discards its output — and every **subprocess it spawns** (the JSON extraction, the `ltm query --help` capability probe, and the `ltm query` itself) SHALL be bounded by that deadline: on expiry the hook SHALL terminate the child **and its own children** (TERM, then KILL — this is not a process group, which would kill the hook itself) and continue with the degradation path. The plugin's hook manifest SHALL declare a timeout of 28 seconds, below Claude Code's 30-second default. Two cheap steps run before the deadline region and are not bounded by it: reading stdin (`cat`, which the caller closes) and the raw cue grep against a local file; both are bounded by construction. `mktemp` failure before the gate is the one silent exit (no notice, no stat line) because it precedes any knowledge of whether the prompt is even a cue match — every other admitted-but-incomplete path prints one notice.

When the gate admits a prompt but recall cannot complete — `python3` is absent, the hook input cannot be parsed, `LTM_BIN` is relative, the `ltm` binary is absent, the `cwd` is missing or cannot be entered, the capability probe times out, the binary does not support `--format recall`, `ltm query` exits non-zero, or the deadline fires — the hook SHALL print exactly one line to stdout of the form `ltm：本輪回想未完成（<reason>）；可手動呼叫 ltm_query`, where `<reason>` names the specific condition **without** echoing the CLI's stderr, and SHALL exit 0. The one exception is the too-old binary, which SHALL be noticed once per session (keyed by `session_id`) and silent for the rest of that session, because until the next release every gated turn would otherwise carry the same line.

#### Scenario: Guard fires on a large backlog

- **WHEN** the gate admits the prompt and `ltm query` has not returned by the deadline
- **THEN** the hook terminates the `ltm` child and its children (not a process group), prints the single notice line with reason `逾時 <guard> s`, and exits 0 before the 28-second hook timeout

#### Scenario: The capability probe is bounded too

- **WHEN** `ltm query --help` does not return by the deadline
- **THEN** the hook prints the notice line with reason `ltm 版本探測逾時` within the deadline and never reaches the 28-second hook timeout

#### Scenario: Binary too old, once per session

- **WHEN** the installed `ltm` rejects `--format recall` and three gated prompts arrive in the same session
- **THEN** the first prints the notice line naming the minimum required `ltm` version and stating it is shown once per session; the second and third exit 0 with empty stdout; a gated prompt in a different session prints the notice again

#### Scenario: Input that cannot be used is a notice, not a crash

- **WHEN** `LTM_BIN` is `./ltm`, or the hook's `cwd` does not exist, or `python3` is not on `PATH`
- **THEN** the hook prints one notice line naming that condition, runs no `ltm` query, and exits 0

### Requirement: The hook records only closed-set outcome labels

When `LTM_RECALL_STATS_FILE` is set the hook SHALL append one line per invocation of the form `<unix seconds> <label>` where `<label>` is one of `off`, `synthetic`, `miss`, `hit`, `notice`, and SHALL write nothing else — no prompt text, no cue, no session id. When the variable is unset nothing is recorded.

#### Scenario: Stats never contain prompt text

- **WHEN** three prompts run with the variable set: one cue hit, one miss, one Claude-Code-generated shape
- **THEN** the file holds exactly three lines whose labels are `hit`, `miss`, `synthetic` in that order and none of the prompt text

### Requirement: The cue file is a plain-text enumeration that documents its own miss cost

The cue file SHALL be UTF-8 text with one POSIX extended regular expression per line. Lines that are empty or begin with `#` SHALL be ignored. The hook SHALL read the file at the path in `LTM_RECALL_CUES` when set, else `${CLAUDE_PLUGIN_ROOT}/hooks/recall-cues.txt`. The shipped file's header comment SHALL state that the list is an enumeration, that it will miss prompts that refer to the past in other words, and that the cost of a miss is the pre-hook behaviour (no automatic recall). When the file cannot be read the hook SHALL treat the gate as a miss for every prompt and SHALL write one line to stderr naming the path.

#### Scenario: Custom cue file overrides the shipped one

- **WHEN** `LTM_RECALL_CUES` points to a readable file containing only the line `deploy`
- **THEN** a prompt containing `deploy` is admitted and a prompt containing `上次` is not

#### Scenario: Unreadable cue file fails closed

- **WHEN** `LTM_RECALL_CUES` points to a path that does not exist
- **THEN** every prompt is a gate miss, stdout is empty, and stderr contains the path once

### Requirement: Session start reminds Claude that recall exists

The plugin SHALL register a `SessionStart` hook that prints one line to stdout naming the `ltm_query` tool and stating that cue-gated recall is active, for every `source` value (`startup`, `resume`, `clear`, `compact`). The hook SHALL run no query and SHALL exit 0 within 5 seconds.

#### Scenario: Resume also reminds

- **WHEN** a session starts with `source` equal to `resume`
- **THEN** the hook prints exactly one line containing `ltm_query`
