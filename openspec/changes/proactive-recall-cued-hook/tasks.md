Verification: test greps `Sources/` for `ltm:recall` and asserts every occurrence is in the constants file or references the constants (mirrors the repo's existing write-site scan style).
- [x] 3.2 Requirement 'ltm query offers a marker-wrapped recall format sized for hook injection': `ltm query --format recall` renders the marker-delimited block (banner, ≤ k ranked hits with project/timestamp/snippet ≤ 200 chars/sessions/uuid, optional shortfall line, closing marker) and refuses `--json` together with it. Verification: CLI tests asserting first/last line equality, hit count, snippet length bound, and the non-zero exit naming both flags for the conflict.
- [x] 3.3 The recall block never exceeds 4,000 characters: snippets truncate first, then hits drop from the tail, and the closing marker is always last. Verification: unit test on the renderer with 3 hits of 3,000-character snippets asserting length ≤ 4,000, closing marker present, and rank order preserved.

- [x] 5.1 `plugin/hooks/hooks.json` registers `UserPromptSubmit` → `${CLAUDE_PLUGIN_ROOT}/hooks/ltm-recall-gate.sh` (timeout 28) and `SessionStart` → `${CLAUDE_PLUGIN_ROOT}/hooks/ltm-session-start.sh` (timeout 5); both scripts are executable. Verification: `Tests/LTMMCPTests/PluginShellTests.swift` gains assertions that the manifest parses, names both events, and the referenced scripts exist with the executable bit.
- [x] 5.2 Requirement 'The cue file is a plain-text enumeration that documents its own miss cost': `plugin/hooks/recall-cues.txt` ships with the header stating enumeration / will-miss / miss-cost, and the initial cue set from design decision 2. Verification: shell test in `Tests/LTMMCPTests/RecallHookShellTests.swift` asserts the header phrases are present and every non-comment line compiles as an ERE (`grep -E -e <line>` on an empty input exits 1 not 2).
- [x] 5.3 Requirement 'A cue-gated prompt hook injects pointered recall within the hook budget': `ltm-recall-gate.sh` implements the mode switch and gate: reads hook JSON from stdin, strips `<system-reminder>…</system-reminder>` spans from `prompt`, applies `LTM_RECALL_MODE` (`cued` default, `always`, `off`, unknown → `cued`), matches with `grep -E -q -f <cue file>`, and on a miss exits 0 with empty stdout. Verification: shell tests feeding synthetic hook JSON for each row of the spec's gate-outcome table with `ltm` replaced by a stub on `PATH`, asserting stdout and whether the stub was invoked.
- [x] 5.4 Requirement 'Degradation is visible and never blocks the prompt': on an admitted prompt the gate runs `ltm query "<prompt>" --format recall --k 3 --exclude-session <session_id> --max-refresh-seconds 15` from the hook's `cwd` under a 20-second guard, passes the block through verbatim on success, and on guard fire / non-zero exit / missing binary / unsupported flag prints exactly one notice line naming the reason and exits 0. Verification: shell tests with stubs that (a) print a block, (b) sleep 25 s, (c) exit 2, (d) are absent, (e) reject `--format`, asserting one-line notice text and exit 0 for b–e and verbatim pass-through for a.
- [x] 5.5 Unreadable cue file fails closed: every prompt is a miss, stdout empty, stderr names the path once. Verification: shell test with `LTM_RECALL_CUES=/nonexistent`.
- [x] 5.6 Requirement 'Session start reminds Claude that recall exists': `ltm-session-start.sh` prints one line containing `ltm_query` for every `source` value and runs no `ltm` process. Verification: shell test over `startup`, `resume`, `clear`, `compact` asserting one stdout line and that the `ltm` stub was not invoked.
