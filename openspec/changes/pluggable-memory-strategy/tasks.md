## 1. Package skeleton

- [x] 1.1 A Swift package builds and tests clean with four library targets (`LTMCore`, `LTMMemory`, `LTMQuery`, `LTMEval`) and their three test targets, where `LTMQuery` depends on `LTMCore` **only** (deliberately not on `LTMMemory`, so the retrieval side cannot name `FileEventStore`), `LTMMemory` depends on `LTMCore`, and `LTMCore` depends on nothing. (Corrected 2026-08-11: this task originally said `LTMQuery` depends on `LTMCore` and `LTMMemory`, which contradicts `Package.swift` — flagged by the #1 verify.) Verify by running `swift build` and `swift test` from the repository root; both exit zero with the empty suites discovered.

## 2. Anchors

- [x] 2.1 An `Anchor` value carries a source fingerprint, turn identifier, normalized content hash, and span range; its hash covers the normalized span text only, so two anchors over identical text but differing author role and timestamp hash alike while a one-character text difference does not. Dereferencing returns either the addressed text or an explicit orphaned result naming the hash mismatch, never the text found at a disagreeing location. Verify by tests asserting hash equality across differing role and timestamp, hash inequality on a one-character change, the orphaned result after mutating a synthetic fixture, and that no text is returned in that case. Satisfies requirement "Anchor addresses corpus text by content, not by index identity" and design decision "Anchor by content, not by chunk identity".
- [x] 2.2 Anchors survive a rebuild of the derived index under different chunking parameters — every anchor recorded under one chunk size and overlap still dereferences to identical text after a rebuild under a different chunk size with no overlap. Verify by a test that runs both chunking configurations over the same synthetic fixture and asserts text equality per anchor. Satisfies requirement "Anchor addresses corpus text by content, not by index identity".

## 3. Event store

- [x] 3.1 An `Event` value carries kind, anchor, timestamp, generation identifier, and ranking policy identifier, with the kind restricted to the closed set `shown` / `opened` / `cited` / `pinned` / `dismissed`, and a pin event additionally carrying a random note reference that differs between two pins of identical note text. Verify by a test asserting rejection of an out-of-set kind and inequality of two note references produced for the same note text. Satisfies requirements "Event records carry pointers and statistics only" and "The event kind set is closed", and design decision "Store events, not aggregates".
- [x] 3.2 A populated event store serializes to output containing none of the fixture corpus strings, none of the fixture query strings, and none of the fixture note strings. Verify by a test that serializes a store built from known synthetic strings and searches the serialized bytes for each of them, asserting zero occurrences. Satisfies requirement "Event records carry pointers and statistics only".
- [x] 3.3 The event store exposes append and range-read only, preserves append order on read-back, and surfaces an append failure to the caller instead of dropping it. Verify by a test asserting round-trip order over five appends and a second test asserting a reported failure when the backing location is not writable. Satisfies requirement "The event store is append-only".

## 4. Projection

- [x] 4.1 Projection maps an event sequence plus an evaluation instant to per-anchor statistics as a pure function that writes nothing back to the store, reinforces on `opened` / `cited` / `pinned`, suppresses on `dismissed`, treats an anchor with twenty `shown` events and nothing else exactly as an anchor with no events, and leaves orphaned anchors out of the result without raising. Verify by tests asserting result equality across repeated projection, an unchanged store event count, equality between the impressions-only and empty anchors, and absence of the orphaned anchor from a projection that completes normally. Satisfies requirements "Projection derives per-anchor statistics without persisting them" and "Only deliberate interactions reinforce", and design decision "Only deliberate interactions count".

## 5. Strategy seam

- [x] 5.1 A candidate type carries a base score and a relevance band, and `MemoryStrategy` exposes one operation from an ordered candidate list plus a projection to a result list where each result carries its displacement and a reason, with retrieval never reading the event store and no strategy reading the corpus. Verify by a test asserting the returned list is a permutation of the input, a test asserting every result exposes both fields including a zero-displacement reason, and a dependency assertion that the retrieval target does not link the event store. Satisfies requirements "MemoryStrategy is the sole seam between retrieval and memory" and "Every result carries displacement and reason", and design decision "One seam, and projection is a function".
- [x] 5.2 The `archival` strategy performs no reordering: it returns the input order with every displacement zero and produces identical output whether given an empty projection or one dense with reinforcing events. Verify by a test running both projections against the same candidates and asserting order equality and all-zero displacement. Satisfies requirement "The archival strategy performs no reordering".
- [x] 5.3 The `human-like` strategy promotes a band peer with recorded `cited` events above one without and reports a reason naming the citation signal; reordering across a band boundary and reordering beyond the configured displacement bound each fail loudly rather than being clamped or ignored; and an orphaned anchor receives no promotion while the invocation completes normally. Verify by a test asserting the promoted order and matching reason, two tests each asserting a reported violation naming the band boundary and the bound respectively, and a test whose most reinforced anchor is orphaned asserting zero displacement for it. Satisfies requirements "Reordering is confined to a relevance band", "Promotion is bounded; demotion is a reported consequence", and "Orphaned anchors do not influence ranking", and design decision "Reorder within relevance bands, bound the displacement".
- [x] 5.4 The displacement bound is construction-time configuration defaulting to one position, recorded in the strategy's own doc comment as provisional pending an evaluation set, and strategy identity follows the consumed signal set so two differently-bounded `human-like` instances report the same identifier. Verify by a parameterized test over bounds one and three asserting resulting positions, a test asserting identifier equality across those two constructions, and a content review confirming the doc comment records the default as provisional. Satisfies requirements "Promotion is bounded; demotion is a reported consequence" and "Strategies are distinguished by mechanism, never by magnitude".

- [x] 5.5 The `conservative` strategy reorders only where base scores are exactly equal within a band, ordering tied candidates by strength and leaving differently-scored candidates untouched, so that three strategies coexist and are distinguishable by mechanism rather than by magnitude. Verify by a test asserting tie-breaking on an all-tied band, a test asserting zero displacement on a strictly-decreasing band despite heavy reinforcement, a test asserting that `human-like` with a bound of zero does **not** reproduce tie-breaking, and a test asserting the three shipped strategies report distinct identifiers. Satisfies requirement "Strategies are distinguished by mechanism, never by magnitude". (Added 2026-08-15 by the #17 ruling, which restored a tier an earlier draft had removed on a half-true argument.)

## 6. Comparison

- [x] 6.1 A query class labeller maps a query to exactly one of `cjk-2char`, `cjk-3char`, `cjk-4plus`, `latin-alnum`, `mixed`, and retains no query text beyond the call. Verify by a table-driven test covering one query per class and asserting the returned label. Satisfies requirement "Presentation records carry a query class label and no query text".
- [x] 6.2 The interleaving harness returns a presented list containing each candidate exactly once plus a presentation record that attributes each presented anchor to exactly one contributing strategy, reports no preference when the two rankings are identical, and serializes with the class label, strategy pair, generation identifier, and attribution retained but no query string present. Verify by a test over a differing pair asserting single-strategy attribution per position, a test over an identical pair asserting the null-comparison outcome, and a serialization test searching for each fixture query string and asserting zero occurrences alongside the four retained fields. Satisfies requirements "Comparison is performed by interleaving, not by replaying stored queries", "Each presented position is attributed to exactly one strategy", and "Presentation records carry a query class label and no query text", and design decision "Compare by interleaving, not by replay".
- [x] 6.3 A comparison report carries one row per query class with that class's observation count and never an aggregate row alone, credits only `opened` / `cited` / `pinned` while counting `dismissed` against the crediting strategy, uses each strategy's own presented count as the per-presentation denominator, and reports data spanning more than one generation identifier as such with a per-generation breakdown instead of a pooled figure. Verify by a test over synthetic events spanning three classes asserting the row set, counts, and denominators, plus a test over two generation identifiers asserting the spanning flag and both per-generation rows. Satisfies requirements "Comparison results are reported per query class", "Comparison credits only deliberate interactions", and "Comparison spanning index generations is reported as such".
