## Assumptions Challenged

這個設計把「source 唯讀」偷換成「source 的身分與內容永遠穩定」。兩者完全不是同一件事。專案目錄可能被搬移、session 檔可能被截斷或重寫、UUID 可能因匯入或工具版本而改變，甚至整個 `~/.claude/projects/` 可能未被備份。此時 `memory/ltm.sqlite` 雖被稱為 canonical，實際上只是依附於外部檔案的懸空中介資料；它既不能獨立還原內容，也未必能證明 pointer 仍指向原來那段文字。尤其 co-retrieval edge 明確連到 chunk，而 chunk 是切分演算法的產物；只要從 500/80 改成其他切法、修正 parser，或 embedding 模型版本變更，canonical memory 就會引用已不存在的 derived identity。較合理的替代是使用穩定 anchor，例如 `(source file fingerprint, turn UUID, normalized-text hash, span offsets)`，並把所有使用事件寫成 append-only event log；`strength`、edge 與其他聚合值則一律改為可重算的 derived projection。

「`rm -rf derived && ltm build` 必須等價」也缺乏可操作的等價定義。`NLContextualEmbedding` 隨 OS 更新可能替換權重或 tokenizer，SQLite/FTS tokenizer、Unicode 正規化、JSONL parser 與 chunker 版本也都可能改變。重建後能成功搜尋，不代表向量、排名或舊查詢結果等價。若用途包括稽核決策，僅有 `--pure` 並不能重現歷史 baseline；還需要保留 code version、parser version、chunking manifest、embedding model fingerprint、SQLite version、fusion 參數與完整 generation ID。否則「索引可拋棄」只是維運上的可重建，不是稽核上的可重現。替代做法是 generation-based derived store：每次全量建置產生 immutable generation manifest，查詢歷史記錄所使用的 generation，舊 generation 可依保留政策刪除，但不能假裝任何新重建都與舊結果等價。

「零提取即可支撐跨 session 觀點演變」是最薄弱的核心假設。依 query 撈片段再按 timestamp 排序，只能產生「被目前用詞召回的歷史片段」，不能識別主張、立場、否定、保留語氣、撤回、因果依據或誰的觀點。若早期使用「近似搜尋」、後期改稱「ANN」，再後來結論是「不需要索引」，單一 query 不保證覆蓋三個語彙階段。排序也不等於演變：同一天引用別人的反方意見、假設性討論與最後決策，單靠時間無法區分。所謂「撈出所有提到某主題」在有限 top-k 檢索中尤其是假命題。可替代為 derived、可丟棄且帶來源 span 的 temporal claim table；抽取錯誤不進 canonical，每條 claim 都能回到原文核對，反而比把原始片段按時間堆疊更能暴露衝突與遺漏。

「LLM 提取只用於 routing 就安全」同樣站不住腳。Routing error 會決定哪些證據永遠不進上下文，屬於不可見的 omission bias；answering error 至少可能從引用與原文被發現，routing 漏掉的反證通常沒有任何警示。因此用途不會消除失真，只會改變失真的位置。更安全的替代不是全面禁用提取，而是讓提取結果只作為額外 candidate generator，永遠與 lexical、embedding、時間鄰接及使用者指定 alias 並行，且在輸出中標示各候選由哪一路召回。

所謂「模仿人類記憶」也沒有形成可驗證的工程前提。Wixted & Ebbesen 的群體實驗曲線不能直接證成「一個 chunk 被檢索後加 0.3」；檢索曝光、實際閱讀、採納、引用與事後判定有用，是完全不同的事件。這裡沒有 representation consolidation，只有 scalar reranking；沒有真正的 spreading activation，只有受既有排名與 top-k 截斷污染的 co-retrieval 統計。把這些機制命名為人類記憶，不會替參數提供效度。替代方案是放棄心理學類比，以明確產品目標定義訊號：例如只讓 `opened`、`cited`、`pinned`、`dismissed` 影響個人化，不讓單純 `shown` 或自動檢索增加 strength。

隱私假設則直接自相矛盾。「canonical 只存指標與統計」和 pin 儲存「使用者自己寫的一句話」不能同時成立；那一句話完全可能包含學生姓名、未發表結論或第三方逐字內容。專案路徑、session 關聯、時間戳與 co-retrieval graph 本身也能洩漏敏感關係。更嚴重的是，MCP 將原文送入當前 Claude context 時，資料是否對外傳輸取決於實際模型與客戶端路徑，而不是 embedding 是否在本機。替代方案應是 project-level ACL、讀取前明確授權、敏感欄位加密，以及把 user-authored note 放入獨立的 opt-in encrypted store，而不是用 schema 宣稱零內容後再設例外。

## Failure Modes

1. **Embedding generation 混用。** 觸發條件是 macOS 更新 `NLContextualEmbedding` 後只做增量 ingest：舊 chunk 的向量來自 model A，新 chunk 來自 model B，但都被寫入同一個 `vectors.bin`。兩個向量空間即使同為 512 維也不保證可直接 cosine，比較結果可能無意義。若 `state.json` 沒有模型 fingerprint，系統甚至不會知道應全量重建。替代防線是把 embedding model identifier、asset revision、locale 與 normalization version 納入 generation key，任何差異都建立新 generation，禁止原地混寫。

2. **SQLite、vector file 與 ingest state 發生 split-brain。** 觸發序列可以是：先插入 `chunks` row、再 append `vectors.bin`、最後更新 `state.json`，但程序在任一步驟 crash。重啟後可能出現 row 指向缺失向量、向量 offset 錯位，或 `processedBytes` 已前進卻沒有完整資料。session-start hook 又可能與仍在 append JSONL 的 Claude process 競爭，讀到半行 JSON。替代方案是 staging generation、checksum table 與原子 manifest swap：所有檔案完成且驗證 row count、vector length、source checkpoint 後，才把 `CURRENT` 指向新 generation；尾端不完整 JSON line 不得推進 checkpoint。

3. **非 append 修改被漏檢或造成高成本退化。** 若 `prefixHash` 只涵蓋固定開頭，檔案中段被修改但開頭與 size 未變時會誤判可續讀；若 hash 涵蓋全部 `processedBytes`，每次 session-start 都要重讀大量舊檔，所謂數秒增量會隨 corpus 成長退化。檔案被 replace、mtime 精度不足或備份工具保留 mtime 也會破壞判斷。可替代為分塊 Merkle hash、filesystem identity、tail checkpoint 與內容定址的 turn anchor，而不是依賴 `(size, mtime, prefixHash)` 這種脆弱組合。

4. **Strength 正回饋會在 cutoff 附近放大，±5% 並不是安全上限。** 觸發條件是寬泛 query 反覆顯示同一批 top-k；如果「被提取」包含 shown 而不是 opened，使用者甚至不必讀取，既有高排名結果就會持續增強。當大量候選分數密集時，5% 足以跨越很多名次；反過來，若真的是嚴格 tie-breaker，非完全同分時它根本不會生效。「tie-breaker」與「±5% 調分」是兩種不同演算法，不能同時成立。替代方案是只記錄明確互動事件，以每個 query/session 去重，並直接限制最大 rank displacement，例如最多移動一名，而不是限制一個未校準分數的百分比。

5. **RRF 後的百分比沒有穩定語義。** RRF 是 rank-based、query-relative 的分數，輸入列表截斷深度一改，融合分數就變；把它正規化到 `[0,1]` 也不會使其天然可跨 query 比較。某 query 第一與第二名差距可能極小，另一 query 則很大，同樣 5% 不代表相同證據強度。具體替代是以 held-out relevance judgments 校準 score，或乾脆不要對 RRF 分數乘 boost，而採 lexicographic ordering：先依純檢索 relevance bucket，再於同 bucket 內使用明確互動訊號。

6. **Co-retrieval edge 會學到 UI 與 retriever 的偏差，而非記憶關聯。** 只要某段 boilerplate、總結 turn 或常用專案因現有 ranking 經常進入 top-k，它就會與大量不相干 chunk 共現，形成 hub。自動 agent 重試同一 query、一次大量展開結果、或 session 很長，都會使 edge count 爆增。衰減只能讓舊偏差逐漸變弱，不能消除共同曝光的 confounding。替代是只以「使用者實際共同 opened/cited」建邊，做 per-session 去重，並使用 lift、PMI 或 hub penalty，而不是 raw co-retrieval count。

7. **時序聚合會產生錯誤的觀點演變敘事。** 例如早期 turn 寫「先假設需要 ANN」，中期引用他人說「ANN 是必要的」，後期寫「實測後撤回上述假設」。若 chunk boundary 把否定詞和主張切開、向量漏掉「撤回」片段，時間線就會顯示兩次支持 ANN、一次無關結果。跨 session clock skew、resume 舊 session、匯入歷史檔案或缺 timestamp 也會讓排列順序失真。替代是同時保存 message order、session order、ingest time 與原始 timestamp，並抽取帶 polarity、speaker、modality、evidence span 的 derived claims；無法判定時必須標成 ambiguous，而不是讓時間排序暗示演變。

8. **固定 500 字元 chunk 會破壞語義與排序。** 長程決策的前提、結論與例外可能跨多個 chunk；80 字元 overlap 並不能保證涵蓋中文句界、Markdown code block、表格或引用範圍。命中 chunk 後回傳整個平均 2,386 字元的 turn，又會把不相關內容和歷史指令一起灌入上下文，造成 token 浪費與 prompt injection。替代是結構感知切分：先依 message、段落、句子、code fence 與標題切分，再以 parent-child retrieval 回傳命中 span 加有限鄰接，而非無條件整個 turn。

9. **中文 lexical retrieval 可能名義存在、實際無效。** 若 FTS5 使用不適合中文的 tokenizer，BM25 對繁簡轉換、專有名詞、英文縮寫夾中文與無空格詞組的 recall 會極差，RRF 就退化成向量路徑主導。查詢「擴散激發」未必命中「spreading activation」，「向量索引」也未必命中「ANN」。替代是明確採用 CJK trigram 或可驗證的中文 tokenizer，建立繁簡與術語 alias 的 derived query expansion，並分別報告 lexical-only、vector-only 與 fused recall。

10. **敏感資料會跨專案與跨信任邊界洩漏。** 在專案 A 的 session 中查一個普通術語，可能召回專案 B 的學生資料或合作者 IP；若 MCP 結果被送進遠端 Claude context，「embedding 全本機」並不能阻止外傳。歷史原文中若包含「忽略先前指令」之類文字，當前模型還可能把被檢索內容當成指令執行。替代防線是預設只搜目前 project、跨 project 需使用者確認、結果以 untrusted-data envelope 傳遞、禁止歷史文字取得 tool authority，並提供 metadata-only preview 後再人工批准 `read`。

11. **Pointer 會在重建後失效或誤指。** 只要 parser 修正造成 turn 合併、chunk 編號重排，canonical edge 或 strength 若依 row ID/chunk ID 就可能指到別段內容。更糟的是 row ID 被重用時，表面上 pointer 有效，實際指向錯誤原文。替代是每次 dereference 都驗證 content hash；不一致時標記 orphan，禁止靜默套用舊 strength，並提供 anchor migration 工具。

12. **工具 payload 完全不索引會切斷決策證據。** 很多觀點改變不是出現在自然語言 turn，而是由 test failure、benchmark、compiler error 或 command output 觸發。只存「執行了 benchmark，成功」無法搜尋造成決策的數字或錯誤訊息，時間線因此只留下結論而漏掉原因。替代是對 tool payload 建獨立、預設關閉且受 ACL 控制的 derived index，至少索引 stderr、測試名稱、關鍵數值與 source pointer；不能用資料量大當作完全失明的理由。

## Alternative Approaches

應改成「穩定來源錨點＋canonical 事件日誌＋版本化 derived projections＋來源可核對的 temporal claim layer」，而不是把演算法聚合狀態直接封為 canonical。建議的分層如下：

```text
~/.claude-ltm/
├── generations/
│   └── <generation-id>/
│       ├── manifest.json
│       ├── index.sqlite
│       ├── vectors.bin
│       ├── claims.sqlite
│       └── validation.json
├── canonical/
│   ├── events.sqlite
│   └── anchors.sqlite
└── private-notes/
    └── encrypted.sqlite
```

`anchors.sqlite` 只保存穩定 pointer：source fingerprint、project、session UUID、turn UUID、span offsets、normalized content hash。`events.sqlite` 使用 append-only 事件，例如 `result_shown`、`turn_opened`、`turn_cited`、`pin_added`、`pin_removed`、`result_dismissed`，並記錄當時的 generation 與 ranking policy。它不直接保存 `strength=0.73` 這種受特定公式綁定的狀態；strength、decay 與 edge 都從事件重算，因此公式更換、bug 修正與 counterfactual evaluation 不會破壞 canonical。儲存成本只是每次互動數十到數百 bytes，和 3.72 GB source 相比不構成理由；複雜度增加集中在 event projection，換來的是可稽核與可遷移。

跨 session 觀點演變不應依賴「零提取」。可以建立完全 derived 的 temporal claim table，每筆至少包含：

```text
(subject, predicate, object, polarity, modality,
 speaker, event_time, source_anchor, source_span,
 extractor_version, confidence)
```

本機 extractor 可以是 `FoundationModels`，但其輸出不作答案，也不成為 canonical truth；它只增加候選召回與分組。查詢時並行使用 FTS/CJK trigram、embedding、alias expansion、claim retrieval、相鄰 turn expansion 與時間範圍，再把支持、反對、撤回、條件變更的原文 span 並列。這比純時間排序多了抽取成本，也需要處理 extractor versioning，但錯誤可由 source span 揭露，重建成本只是另一個 derived generation。相較之下，現行方案的 omission 沒有 provenance，使用者甚至不知道哪個歷史語彙階段沒被搜到。

排名應採 deterministic retrieval 為預設，個人化只使用高品質明確事件。可以先以 RRF 得到 base rank，再把候選分成 relevance bands；只有同 band 內才依 `opened/cited/pinned/dismissed` 排序，而且每個 query/session 只計一次。對 co-access association，應依共同 opened/cited 建邊，使用 PMI/lift、時間窗與 hub penalty，並單獨顯示其來源統計。這仍保留「過去常一起使用」的功能，但不會把自動曝光誤當成使用者記憶。其運算成本高於 raw count，資料量卻很小；安全與可解釋性遠高於目前未定義的 boost。

索引層可保留 exact cosine 作 correctness oracle，但不應拒絕 ANN。較合理的是同時提供 derived HNSW 或其他 ANN index，預設依資料規模與裝置選擇，並以抽樣 exact search 測 recall。280,000 vectors 在目前硬體或許能暴力掃描，但每個 query 讀取約 583 MB，冷 cache、低記憶體裝置、並發 query、多 query expansion 與 corpus 成長都會放大延遲和能耗。ANN 增加少量建置與維護複雜度，卻仍是可拋棄 derived artifact；它不會破壞三條不變式。

隱私方面，應把「內容是否 canonical」與「內容是否敏感」分開處理。Derived FTS 本身含完整 plaintext，並不因可刪除而安全；user-written pin 更不可能靠「一句話」免除敏感性。應使用 OS-level protection 或 SQLCipher、限制檔案權限、處理 SQLite WAL/temporary files、依 project 設 ACL，並將 private notes 獨立加密。若堅持 canonical 不存文字，pin 就只能存 pointer、固定標籤或本機 keychain 中的加密 note，不能一面宣稱 schema 禁止原文、一面允許自由文字例外。

## Trade-off Counterarguments

設計把「避免抽取失真」置於「能否真正回答觀點如何演變」之上，形成錯誤二分。Derived extraction 不必成為 canonical，也不必取代原文；它可以只是高 recall 的額外入口，每筆結果附 source span、confidence 與 extractor version。完全不抽取並沒有消除錯誤，只是把錯誤改成 embedding 漏召回、chunk 邊界失真、時間排序誤導與當前 Claude 臨場解讀。這些錯誤通常比結構化抽取更難量測，因為缺失的證據不會出現在畫面上。應優先犧牲一部分建置成本，換取跨術語、跨立場與跨時間的可觀測 recall。

「索引可拋棄、記憶 canonical」的分家也切錯了邊界。真正 canonical 的應是使用者行為與顯式註記事件，不是依某條 power-law 算出的 strength，也不是引用 derived chunk ID 的 edge。聚合值屬於演算法 view，理應可重算；source anchor 才需要穩定。現行分家看似避免把原文備份出去，實際上同時犧牲了 pointer durability、演算法可遷移性與歷史重現，卻仍保留敏感 metadata 和自由文字 pin。更合理的取捨是保存最小 append-only events、加密敏感 note、對每個 anchor 做 hash 驗證，並把所有 strength/edge projection 放回 derived。

拒絕 ANN 所換得的只是少一個目前尚未需要的元件，犧牲的是成長餘裕、冷 cache latency、能源效率與 multi-query retrieval。一次 exact cosine 若真的讀取 583 MB，不能只用熱 cache 的「毫秒級」數字概括；同一 query 做 alias expansion、時間切片、反事實比較或多 agent 並行時，記憶體頻寬會直接成為瓶頸。ANN 完全可以是可刪除的加速層，exact search 則保留作驗證與 fallback，沒有必要把二者當成互斥架構。

「strength 只微調，因此風險可控」則犧牲了複雜度與可重現性，卻沒有換得可證明的效益。若它真的只在完全同分時 tie-break，作用近乎為零；若能造成 5% 分數變化，則在密集候選中可能大幅改變 top-k。這個中間地帶既不是 archival，也沒有足夠強的 personalization，更不能被稱為 human-like。較合理的選擇是預設完全 deterministic，僅在有 `opened/cited/pinned/dismissed` 等明確訊號時啟用可解釋的 rank rule，並直接顯示「因曾引用而上移一名」，不要使用難以校準的心理學 strength。

「不 archive 以保留全庫 recall」也沒有解決真正的 recall 問題。低 strength 是否留在 corpus，對 lexical/embedding candidate generator 的語彙漏召回沒有幫助；未被 query 表達命中的內容仍然不可見。它只避免第二階段把已召回候選排除，卻把這件小事包裝成對抗永久遺忘。應把資源投入 query expansion、CJK tokenizer、tool evidence、temporal claims、相鄰上下文與負面相關判定，這些才會增加候選集合中的相關證據。

最後，「原文注入保真」犧牲的是上下文安全與可用性。完整 turn 可能混入無關話題、舊指令、敏感資料和 prompt injection；原文並不會因未經摘要就自動變成安全證據。更合理的取捨是先回傳 metadata、命中 span 與有限鄰接，將內容標記為 untrusted historical data，跨專案讀取要求確認，必要時再展開完整 turn。對長期記憶工具而言，優先維護證據邊界、來源身分與存取控制，比模仿人類的可得性偏誤更重要。
